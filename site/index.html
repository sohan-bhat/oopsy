    How it works

    1. It hooks in

      oops init adds a small hook to your shell and to your coding agents, so every command passes Oopsy on its way to run.

    2. It snapshots first

      When a command is about to destroy files, Oopsy clones them first. Copy on write on APFS and Linux reflinks makes that instant and nearly free on disk.

      It reads the command with a real shell parser, so it knows rm, mv, cp, sed -i, dd, find -delete, rsync --delete, redirects, and git reset, clean, checkout, branch -D, stash drop and push --force.

    3. You type oops

      oops shows what it will bring back, then restores it. oops list shows the rest, and oops undo <id> brings back any one of them.

      It never overwrites. If a file exists again, the saved copy lands next to it as name.oops-42.ext.

    Postgres, too.

    Run oops db proxy --upstream postgres://... and point your app or agent at the proxy instead. Before any DROP TABLE, TRUNCATE, DELETE or UPDATE reaches the database, Oopsy copies exactly the rows it is about to touch, inside the same transaction, so a rollback discards the snapshot too.

    Or skip the setup: oops db wrap -- npm run dev runs your command with DATABASE_URL pointed at a temporary proxy.

    What it does not catch

    • Programs that delete things themselves. Oopsy reads the command line, so make clean, npm run reset or a script that removes files is invisible to it.
    • File edits made in an editor, or by an agent's own edit tool instead of the shell.
    • Anything remote, like ssh, kubectl delete or terraform destroy.
    • Database changes that skip the proxy, plus DROP DATABASE, DROP VIEW and upserts.
    • Huge folders on filesystems without copy on write. Plain copies stop at 1 GB, and Oopsy tells you what it skipped.
    • A dead disk. Snapshots live next to your files, so keep a real backup too.

    Questions

    Why not just Ctrl+Z?

    Undo lives inside your editor. rm, git and your database never ask your editor first, so once a file is gone from disk there is no history to step back through. In a terminal, Ctrl+Z only suspends the running job.

    Why not git?

    Git protects what you committed. Uncommitted edits, untracked files, .env and everything in .gitignore are exactly what rm -rf and git reset --hard wipe out. Oopsy covers the work between commits.

    Why not Time Machine?

    Time Machine runs about once an hour, to another disk, and getting a folder back means scrolling through a timeline. Oopsy snapshots the exact moment before the command and restores in one word. Keep both.

    How much disk does it use?

    On APFS and on Linux filesystems with reflinks, like Btrfs and XFS, a snapshot is a copy on write clone. It shares storage with the original and costs almost nothing until the files change. On other filesystems Oopsy falls back to a regular copy, up to 1 GB per command. Snapshots are kept for 7 days and capped at 5 GB in total, and you can change both in ~/.oops/config.json.
